## Phase 5 picks

- **A. Idea track record.** The `daily` table already keeps each day's ideas, and mock data can be backdated through `MarketData(today=...)`. Show how each past idea did at today's price, compared with simply holding SPY. Why a recruiter cares: the product grades itself in public, which reads as honest and data-driven.
- **B. Exit-plan alerts on paper positions.** Turn each trade's `management` rules into flags: hit 50% of max profit, 21 days or fewer to expiry, or price through breakeven. Why a recruiter cares: it closes the loop from entry to exit, which shows product judgment about risk and not just picking stocks.
- **Cut:** the earnings guard (no data source, see above), and the morning summary (low visual payoff; B covers most of it).

## Appendix: M1.10 repro and acceptance (for qa-tdd)

**CHL-R1 (P1, auto). The screener returns a 500 when a symbol isn't in the universe.**
- Repro in the UI: Screener, Symbols "AAPL, NFLX, XYZQ", Screen. It shows "Request failed (500)".
- Repro in the API: `POST /api/screen {"criteria":{"scope":"list","symbols":["ZZZZ","AAPL"]}}` returns a 500 (`KeyError` in `engine.analyze`).
- Given a list scope where some symbols aren't in the universe
  When the screen runs
  Then the response is 200, rows come back for the known symbols, `unknown_symbols` is `["ZZZZ"]`, and the UI says "ZZZZ isn't in Charlie's universe yet."
- If every symbol is unknown, the response is 200 with no rows and the same list.
- Test this through both `TestClient` and `Api.route` (static parity).

**CHL-R2 (P1, auto). The data-source label is wrong when sources are mixed or the result is empty.**
- Repro 1, mixed: `CHARLIE_DATA=auto`, profile interests "video games, fintech". `/api/ideas` reports `mock (demo data…)` while all 3 ideas have quote source `cboe (delayed)`, because EA and FI fell back to mock. The badge says "Demo data".
- Repro 2, empty: mock mode, `POST /api/screen {"criteria":{"domains":["nope"]}}` reports `live (delayed)`, because `all([])` is True (`engine.py`, `screen` and `daily_ideas`).
- Given analyses that are all live, all mock, mixed, or empty
  When ideas or a screen are returned
  Then `data_source` is "live (delayed)", "mock…", "mixed…" (listing the mock symbols), or the market mode, in that order
  And each idea and screen row has a `price_source` field.
- Test with a stub market where one symbol's quote has `source: "mock"`.

**CHL-R3 (P1, auto). Live ideas can be built on fake prices for symbols Cboe won't serve.**
- Repro: `CHARLIE_DATA=auto`. Any profile whose circle includes FI or EA gets mock prices and chains for them (Cboe returns 403 as of Oct 28).
- Given live mode and a symbol whose quote fell back to mock
  When daily ideas run
  Then that symbol is left out of the ideas and listed under `skipped`, with the reason "no live price today"
  And `/api/ticker/<sym>` still works, labeled as demo.
- Also check FI and EA against current listings and replace or drop them in `universe.py`. Log that change under "Decisions to review" in HANDOFF.

**CHL-R4 (P1, auto plus one e2e). Live prices are shown next to demo fundamentals without saying so.**
- Repro: `CHARLIE_DATA=auto` with `CHARLIE_SEC_UA` unset. The header badge says "Delayed data", while the score's value factor, P/E and FCF yield come from demo earnings set against the real price.
- Given live prices and SEC fundamentals turned off
  When Today loads
  Then `/api/status` `data.fundamentals` is "demo", the badge reads "Live prices · demo fundamentals", and its tooltip says the scores use illustrative fundamentals.
- Test the API field and the badge text (from the JS function or the e2e test).

**CHL-R5 (P2, auto). Bad input returns a 500.**
- Repro: `POST /api/screen` with `{"criteria":{"min_score":"abc"}}` or `{"criteria":{"delta":"x"}}` returns a 500. `POST /api/paper {"trade":{"symbol":"AAPL","strategy":"shares","legs":[{"x":1}]}}` also returns a 500.
- Given a non-numeric criterion or a leg that's missing fields
  When the request is posted
  Then the response is 422 with a plain message naming the field
  And there is no traceback in the server log.

**CHL-R6 (P2, auto). Paper trades can be duplicated without warning.**
- Repro: on Today, click "Paper trade this" twice. Two identical ABT positions open, each with the toast "Paper trade opened". Capital at risk then reads $26,110 against $25,000 of capital, with no warning.
- Given an open position with the same symbol, strategy and legs
  When the same trade is posted
  Then the response is 409 "You already have this paper trade open."
  And the button reads "Opened ✓" after the first success.
- Given open max loss plus the new max loss is more than capital
  Then the response includes `warning` and the toast shows it.

**CHL-R7 (P2, auto). Closing a position is silent, and a scratch trade counts as a loss.**
- Repro: on the Paper tab, Close. There's no toast, and the win rate shows 0% for a $0 close.
- Given a position is closed
  Then a toast says "Closed ABT Covered call: P&L $X".
- Given closed trades with P&L above, below and exactly 0
  Then `win_rate` is wins divided by (wins plus losses), and $0 closes are counted as `scratch`.

**CHL-R8 (P2, auto). "Delete my data" leaves paper trades and saved screens.**
- Repro: `DELETE /api/profile`, then `GET /api/paper` and `GET /api/screens` still return the earlier rows. The button says "Delete my data", while the confirm text says trades are kept.
- Given positions, screens, a profile and cached ideas
  When `DELETE /api/profile?all=true` runs (the button's default, with a confirm that lists what goes)
  Then every table is empty and `GET /api/paper` shows 0 positions.
- Without `all`, today's behavior stays. Log this under "Decisions to review" in HANDOFF.
